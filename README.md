# 深鲸记忆 · dsh-memory-doctor


> 跨会话记忆的**管家**：用量体检、重复合并、备份恢复、记忆包迁移。本地明文、零依赖、不上传任何数据。

## 它解决什么

现在大多数记忆插件都在解决「**记住**」。但用久了真正的问题变成：

- 记忆越写越满（运行时记忆有硬上限），到点就被动归档
- 同一条记了两遍、内容差不多但措辞不同
- 「临时/进度」类内容混进长期记忆，占着预算
- 换电脑、团队协作时，记忆带不走

本插件补的就是这三件事，**不改你现有的记忆文件格式**（`~/.mnemon/runtime/` 下的 MEMORY.md / USER.md），
所以它可以和现有记忆插件共存。

## 它自己就是热记忆（不是配件）

每轮对话都会把 `MEMORY.md`（项目/环境记忆）和 `USER.md`（用户画像）**注入 system prompt**，
并附带「记忆维护协议」——所以 Agent 真的会记住，而且知道什么时候该写、写去哪、别重复写。

- 注入预算默认 6000 字符，超了截断并提示归档（不会把上下文吃光）
- 记忆是**明文 Markdown**（`~/.mnemon/runtime/`），你自己随时能看、能改、能带走
- Agent 用自带的写文件工具维护记忆，不需要额外工具调用

## 与别的记忆插件共存 / 替换

本插件默认**负责每轮注入**——装了就该生效，不做「装完却不工作」的插件。

如果检测到 profile 里还有其他记忆插件也在注入，概览页顶部会**明确提示**「两份记忆会重复占用上下文」，
并给出一个「切回对方」按钮：

- **默认**：由深鲸记忆接管注入（体检 / 瘦身 / 备份 / 记忆包同时可用）；
- **切回对方**：点按钮即把深鲸的注入关掉（只改我们自己的配置，**不动对方的插件**），本插件退为「记忆管家」；
- **强制开关**：`MEMORY_DOCTOR_INJECT=0` 关、`=1` 开（优先级最高），或写
  `~/.mnemon/doctor.json`：`{ "inject": true }` / `{ "inject": false }`。

> 之所以不自动停用对方：改用户的 profile 属于越权，插件之间互相封杀最后伤害的是用户。
> 我们靠「默认可用的能力 + 出问题能回滚」争取用户，而不是靠禁用别人。

> 记忆文件是同一份（`~/.mnemon/runtime/MEMORY.md`、`USER.md`），所以替换时内容不用迁移。

## 功能

- **工作项（0.5.19 起）**：把「正在做的事」从聊天记录里拎出来。**工单管现在、记忆管以后** —— 工作项只存任务状态（谁发起 / 凭什么做 / 做到哪 / 卡在等谁 / 产出在哪），不存知识结论；结项时填的「教训」自动写入 MEMORY.md。`observe` 模式只记录不动手，人确认后才允许执行（对应 superagent 的 observe→auto 思路）。面板新增「工作项」页签；工具 `work_item`（create/list/update/move/confirm/close）。

| 功能 | 说明 |
|---|---|
| **写记忆工具** | Agent 可调用 `memory` 工具：`read / append / replace / remove / search / stats / compact`；写入经宿主进程、绕开文件沙箱，自动去重、写前备份、**到 80% 自动压缩**、超上限拒绝 |
| **会话回复存入记忆** | 每条助手回复旁的大脑按钮：预览后一键存入 MEMORY.md / USER.md（自动去重、写前备份、超上限提示） |
| **概览** | 系统状态卡片（记忆引擎 / 运行时记忆 / 归档 / 记忆包）、存储域（根路径+三个子存储）、记忆来源与共存状态、用量（实时曲线 + 历次体检快照，两种口径分开标注）、最近写入 |
| **体检（分级 + 具体动作，0.6.0 / 0.6.2 收口）** | 顶部先给一句结论：**「再归档 K 条（约 X 字节）即可达标」**，K 按「目标 70% × 上限」的缺口与字节降序算出；真实垃圾（重复/临时/低信息量）逐条给「序号 + 30 字摘要 + 为什么 + 合并文案」，纯体积项聚成一张卡（默认收起，可「选中这 K 条」批量勾选或展开全部）；纯体积明确标注「仅体积偏大，不代表内容该删」 |
| **自动压缩（四层）** | 到 80% 自动跑四层管线：L1 无损折叠 → L2 超大条目落盘 → L3 按优先级驱逐 → L4 到摘要线才 LLM 摘要；每层都可恢复、有谱系记录，见下面「压缩」一节 |
| **压缩核对（0.6.0）** | 每次压缩后生成 `压缩报告.md/json`：前后条目数/字节/占上限、各层处理条数、**5 组「原文 → 处理后」抽样对照**、一行结论（信息保留 / 有损但可恢复 / 不可逆项 0 条）。面板「归档」页可看，CLI 可导出 |
| **忽略** | 误报的条目点「忽略」后不再出现在建议里；设置页可一键全部恢复 |
| **瘦身** | 按勾选归档到 `archived/`（**先备份、只移动、不删除**，可回滚） |
| **文档（只读）** | 浏览 `~/.mnemon/documents/` 里的项目文档（只读，不修改） |
| **对比上次** | 与上一次体检对比：新增 / 移除的记忆条目 |
| **记忆包 v2（0.6.0）** | 一键导出 `~/.mnemon/记忆包-日期-xxxx/`：MEMORY / USER / memories.json / **archived 全量（含压缩谱系与原文）** / 配置 / 文档，并生成 `MANIFEST.json`（每文件 sha256 + 字节 + 条目数）。导入**先逐文件校验**，不一致只报告零写入；默认 dry-run，确认才落盘且先整份备份；同名不同内容绝不覆盖、另存 `.导入-<时间>` |

## 压缩（0.5.11 起：四层管线）

`MEMORY.md` 是**整份每轮注入 + 硬上限 10KB**，所以它一定会满。旧版是「到 80% 就归档临时条目 + 把长条压成首句」的一刀切；
0.5.11 改成四层依次尝试，**每一层都能单独恢复，单层失败只降级、不阻断**：

| 层 | 什么时候做 | 做什么 | 怎么恢复 |
|---|---|---|---|
| **L1 无损折叠** | 有连续重复行（同一行 ≥3 次）且真能省字节 | 折叠成一行标记 `⟦dsh-fold-N-<行指纹>⟧`（带指纹，多条记录不串），不丢信息 | `逆变换.json` 的 L1 记录 + `还原折叠()` 逐字节还原；层快照 `1-折叠.md` |
| **L2 落盘** | 单条内容 > 4000 字节 | 全文存 `落盘/条目-N.md`，上下文里留头 480B + 尾 160B + 路径 + SHA256 | 直接读落盘文件；`校验压缩()` 用 SHA256 校验完整性 |
| **L3 软压力** | 70% 只提醒（不改内容）；80% 起驱逐 | 按优先级：临时/进度类 → 可重放指针（已落盘/已归档）→ 超长条目首句化（至少留 3 条） | 被驱逐的进 `归档条目.md`；整份原文在存档根目录 |
| **L4 LLM 摘要** | 前三层压完仍 ≥90%，**且调用方注入了摘要器** | 摘要正文上限 = 上限的 15%（预算预留同样 15%），永远保留最新 1 条原文 | 摘要前全量写 `摘要前-MEMORY.md`；不注入摘要器就跳过（默认不调 LLM） |

每次触发的存档目录 `~/.mnemon/runtime/archived/自动压缩-<时间>/`：

```
MEMORY.md            压缩前全量（整体回滚用）
memories.json        压缩前记忆库
归档条目.md           L3 驱逐出去的条目
落盘/条目-N.md        L2 落盘全文（带 SHA256）
层快照/0-原始.md … 4-摘要.md   每层跑完的样子
逆变换.json          L1 折叠记录 / L2 SHA256 / L3 归档 / L4 摘要
谱系.json            四层各自的状态（ok / noop / 跳过 / 降级）、原因、省下字节
压缩报告.md / .json  前后对比、各层条数、5 组抽样对照、结论（0.6.0）
```

- 入口：`自动压缩({ 文件, 摘要器?, 摘要阈值? })`，写记忆/改记忆前自动触发；也可 `memory action=compact` 手动跑
- 整体回滚：`恢复压缩({ 存档文件名, 确认: true })`（会先把当前内容另存 `.恢复压缩前.bak`）
- 存档完整性：`校验压缩({ 存档文件名 })` → 逐项检查全量存档 / 逆变换 / 落盘 SHA256 / 层快照
- 谱系列表：`压缩谱系()`；同时追加一行到 `archived/压缩谱系.jsonl`（最多保留 200 行）
- 压缩核对：`压缩报告({ 存档文件名?, 最近? })` 读回报告；CLI `node scripts/cli.mjs report --last`
- 清理预案：`生成清理预案()` → `~/.mnemon/清理预案/清理预案-<时间>.md`（待审，不自动删）
- **L4 默认不跑**：插件自己不发 LLM 请求；只有宿主/调用方传入 `摘要器` 才执行，否则该层记「跳过（未注入摘要器）」并降级
- 任何时候都不删除内容：只做「折叠 / 落盘 / 归档 / 摘要」，原文都能从 `archived/` 取回

## 安装

```bash
dsh plugin --profile web add dsh-memory-doctor
```

- 面板安装需要本机有 `pnpm`（DSH 的安装器依赖它）
- 没有 pnpm 也行：下载仓库 → 把整个文件夹放进 `dsh-home/plugins/` → 重启 DeepWhale Desktop
- 装好后侧栏出现「记忆体检」图标；命令 `/memory` 可用

## 本地安装（开发机）

同源两处都要装，否则重启会被随包载荷覆盖：

```bash
bash scripts/install-local.sh
```

它会把当前仓库的 `lib/` + `package.json` 一起装到**随包载荷**（`Resources/bundled-plugins/dsh-memory-doctor`）与**用户插件目录**（`dsh-home/plugins/dsh-memory-doctor`），两处各留 `.bak-<时间>` 备份并校验版本。
⚠️ 桌面端升级（重装 dmg）会换掉载荷 → 升级后重跑一次本脚本即可。

## 使用

- 面板：侧栏「深鲸记忆」图标（大脑图标）→ 概览 / 运行时记忆 / 记忆包 / 归档 / 设置 五个页签

  ```bash
  node scripts/cli.mjs pack export            # 导出记忆包（含 MANIFEST）
  node scripts/cli.mjs pack verify <包目录>    # 只校验，不写
  node scripts/cli.mjs pack import <包目录>     # 预览（dry-run）
  node scripts/cli.mjs pack import <包目录> --apply   # 校验通过才写入，先备份
  node scripts/cli.mjs report --last          # 最近一次压缩核对
  node scripts/cli.mjs plan                   # 生成待审清理预案
  node scripts/cli.mjs check                  # 体检 + 可执行建议
  ```

## 白屏防护（2026-10-27 起硬性要求）

宿主 web 启动时，**任何一个客户端插件激活失败都会让整页显示 "Failed to load plugins"**（白屏）。
本插件三层保证自己永远不会触发这件事：

1. **客户层加载**整体 try/catch：加载期异常 → 降级为空插件（不注册任何槽位），界面照常；
2. **错误边界**：面板与「存入记忆」按钮都用 React ErrorBoundary 包住，渲染期异常只在那一块显示一句提示；
3. **apply() 绝不抛错**：槽位服务缺失、某个槽位注册失败都只记日志跳过。

发布前自动闸门：`npm run preflight`（`scripts/preflight-client.mjs`）模拟宿主加载/激活/渲染，
不通过就发不出去（`prepublishOnly` 自动执行）；同类闸门也用于其它深鲸插件。

## 安全

- 只读写 `~/.mnemon/`；**不做删除**（归档 + 备份）
- 不联网、不上传；无遥测

## 未知边界

- 目前瘦身只处理 `MEMORY.md`（`USER.md` 是人格画像，建议人工编辑）
- 记忆包导入为**追加合并**，不与现有条目冲突时才加；同名归档文件不覆盖，另存 `.导入-<时间>`
- 清理预案只是待审文件，不会自动归档/删除；执行仍在面板里按条目序号手动勾选
